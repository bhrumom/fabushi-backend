# FDN G15 official device MCP production resource/privacy evidence

This slice measures the real shipping `fabushi-fdn-official-device-mcp.service`, not an injected `accountClient` or a mock MCP server.

The production probe is valid only when the controller's deployed `BACKEND_SHA` equals the workflow exact main SHA and its `CORE_SHA` equals the verified current Platform Core main SHA. It samples five minutes of the live Node process and enforces RSS < 150 MiB, single-core average CPU < 1%, state/audit/journal <= 20 MiB, and filesystem free space >= max(1 GiB, 5%). It scans only journal output for credential-like material; it never copies the MCP state file because that file intentionally contains local OAuth state.

The service has `MemoryMax=150M` and `TasksMax=256`. The shipping service now installs a cgroup-scoped netfilter owner before Node starts: loopback is allowed for the private network worker and local ingress, system DNS resolvers are allowed only on port 53, `api.ombhrum.com` addresses are allowed only on TCP/443, and every remaining service-owned packet reaches a final `REJECT` rule tagged `fdn-g15-official-device-mcp-egress`. IPv6 receives the same owner whenever the host has IPv6 enabled. The production probe validates the cgroup jump plus tagged reject rule, snapshots both IPv4/IPv6 counters before and after the five-minute window, exposes the delta as `unexpectedWorkerOwnedPacketsRejected`, and requires that delta to equal zero. Before these bytes are merged and deployed as exact Backend main, production promotion remains blocked; absence of the owner still yields `BLOCKED_EGRESS_REJECT_COUNTER` and must never be recorded as passed G15 evidence.

Pull-request CI validates only the exact shipping process/service contract and probe syntax. Real resource evidence can only come from a workflow-dispatch run on deployed exact main with the production environment.
