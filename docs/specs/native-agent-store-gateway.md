## Requirements and architecture
NAS-R1: narrowly route existing /v1/account/agents collection, Agent detail/store, /v1/account/bots collection/membership, and /v1/account/sync to the existing fixed https://ai.ombhrum.com owner before the broad Core gateway. Keep all other /v1 routes on their current owner.
NAS-R2: preserve request method, query, body and native Authorization/device/idempotency context. Never accept an owner origin from user input, environment or query. No retry/failover after a request may have committed. Missing session is still enforced by the existing stable account resolver; never derive account identity from a device ID or raw token digest.
NAS-R3: do not follow or expose upstream redirects on private state routes; return an explicit unavailable error. Disable caching. Preserve 401/403/404/409 and successful response bodies. Errors must not reveal credentials or private request bodies.
NAS-R4: preserve existing data, schema, limits and CAS/conflict behavior; no conversion of Cursor credentials or fake native APIs. This routing unit does not prove large-file parity, saved environments, native cloud scheduling, sharing/multipart, Desktop file-consumer cutover or deployed acceptance.

## Exact route/method contract
- /v1/account/agents: GET
- /v1/account/agents/:agentId: GET, PUT
- /v1/account/agents/:agentId/store: GET, PUT, DELETE
- /v1/account/bots: GET
- /v1/account/bots/:botId/add: POST, DELETE
- /v1/account/sync: GET
Unsupported methods on these owned paths return 405 with Allow. Other paths fall through. Request body/auth validation remains in existing Node owners.

## Strategy / failure and migration
Add one narrow gateway adapter and order it before platform-gateway. Reuse existing AccountSyncStore and authenticated HTTP integration suites. No database/schema/data migration or new storage binding. A failed write proxy returns 502 with unknown outcome and must be reconciled; no hidden replay. Production rollout follows normal Backend Worker pipeline only after exact-source checks; rollback removes the route and leaves Node account data intact, with the known public 404 limitation explicit.

## Native file HTTP boundary repair (NAS-R5)
Discovery: the existing store supports 8 MiB objects including empty bytes, but both upstream JSON parsers cap bodies at 1 MiB and the PUT handler rejects empty base64. Preserve the existing 8 MiB decoded limit and allow zero-byte files. Introduce one shared JSON parser selector used by the production server and account router: only PUT /v1/account/agents/:agentId/store receives ceil(8 MiB / 3)*4 + 16 KiB JSON bytes; other routes keep 1 MiB. Require canonical padded base64 (empty string valid), reject absent/non-string/malformed data with 400 and decoded oversize with 413 before storage mutation. Keep account authorization, existing CAS/conflict copies and database schema unchanged. Actions HTTP tests must exercise empty/8 MiB round trips, foreign-account denial, malformed/oversize rejection without stored objects, conflict preservation and unchanged unrelated-route body limits. Public deployment and Desktop consumer acceptance remain AC3 pending; this does not establish multipart/sharing parity.

## Native account identity resolution boundary (NAS-R7)
The existing Node account resolver is the private Agent/file identity authority. Its remote /api/auth/user-info call must select only approved native production/isolated-CI origins or explicit HTTP(S) loopback, with no URL credentials/path/query/fragment and no remote HTTP/non-default port. Reject redirects and bound profile JSON to 64 KiB. Only immutable string/safe-integer account IDs from native profile ID fields may become an account namespace; username/email are display metadata and never fallback identity. Preserve explicit trusted local resolveUser and existing isolated test-token behavior; neither device identity nor anonymous scope can satisfy a private account request. Each private request still resolves current native session authority rather than caching account identity across tokens. Failures never include bearer/profile contents. Actions must prove same stable account across different sessions, refusal of username/email-only/malformed profiles, unapproved origins before fetch, oversized/invalid responses, and an actual HTTP redirect destination receiving no call. This repairs the selected existing owner, not a new auth service.
